Дата: 10 октября 2026 года. Проверен текущий рабочий каталог, включая существовавшие до аудита незакоммиченные изменения. Приложение запускалось по адресу `http://127.0.0.1:5173/minigames/`.

Это исходный отчёт до исправлений. Результат последующих изменений и повторной проверки описан в [FIXES.md](FIXES.md).

Реальные регистрация, Email/Password-вход, Google-вход, избранное, отправка комментария и лайк работают в локальной конфигурации. Полное выполнение всех заявленных критериев не подтверждается из-за перечисленных ниже дефектов.

## QA-01 — P1: публикация собирает приложение без Firebase-конфигурации

**Место:** [.github/workflows/deploy-pages.yml](../.github/workflows/deploy-pages.yml), шаг Build; [src/services/firebase.ts](../src/services/firebase.ts), строки 20–36.

В репозитории отслеживается только пустой `.env.example`. Настоящий `.env.local` игнорируется Git. Шаг `npm run build` в workflow не задаёт ни одну из четырёх переменных `VITE_FIREBASE_*`. Переменные/секреты репозитория сами по себе не передаются в окружение шага.

**Воспроизведение:** выполнить сборку в чистом окружении без `.env.local` и четырёх переменных Firebase, как на новом runner. В аудите выполнена отдельная сборка с пустым envDir. В итоговом JavaScript обнаружена конфигурация `{apiKey:'',authDomain:'',projectId:'',appId:''}` и проверка, выбрасывающая `Firebase is not configured`.

**Следствие:** артефакт этого workflow не сможет выполнять Email/Password-регистрацию, вход и Google-вход. Локальная сборка с имеющимся `.env.local` проходит и авторизация работает. Текущая опубликованная версия сайта отдельно не проверялась; вывод относится к проверенному workflow и воспроизведённой чистой сборке.

**Исправление:** передать четыре значения через env шага сборки; проверять их наличие до публикации.

## QA-02 — P1: локальный JSON считается подтверждённой авторизацией

**Место:** [src/features/auth/session.ts](../src/features/auth/session.ts), parseSession/getSession/startSession; [src/services/api.ts](../src/services/api.ts), requireSession и POST-запросы.

**Воспроизведение:** в гостевом режиме записать под ключом `minigames:sholomickiyr:app-session` объект с тестовыми displayName/email и текущим authenticatedAt. Перезагрузить приложение. Никакого входа через Firebase выполнять не нужно.

**Фактически:** getSession возвращает пользователя; шапка и клиентские guards считают его авторизованным. Защищённая операция проходит клиентскую проверку и отправляет POST с userEmail. Отдельные проверки аудита подтвердили и восстановление подставленного профиля, и отправку запроса. API в этих проверках замокан: действия от имени чужих реальных пользователей не выполнялись.

**Причина:** проверяются форма JSON и возраст записи, но не текущая личность SDK. Нет подписки на изменение Firebase-пользователя или сопоставления профиля с ним. POST-запросы передают email без Firebase ID token.

**Ожидание:** локальный профиль использовать как данные интерфейса, а подтверждение входа получать от Firebase. Защищённые действия должны требовать согласованную текущую личность.

**Граница вывода:** если учебный API намеренно принимает только userEmail, отсутствие токена — ограничение этого контракта; аудит не утверждает наличие проверенной уязвимости чужих серверных данных. Клиентский обход guest-mode guards и отсутствие проверки личности подтверждены независимо от этого.

## QA-03 — P2: окно входа не закрывается после входа в другой вкладке

**Место:** [src/app/index.ts](../src/app/index.ts), строки 125–127.

**Воспроизведение:**

1. Выйти из приложения и открыть Login в первой вкладке.
2. Открыть приложение во второй вкладке и войти с правильными данными.
3. Вернуться в первую вкладку.

**Фактически:** профиль в первой вкладке уже обновился, но `.auth-dialog.open === true` и URL всё ещё содержит `?auth=login`. Воспроизведено реальным Email/Password-входом в двух вкладках и отдельным тестом storage-события.

**Ожидание:** закрыть Login/Register и убрать auth, сохранив прочие параметры URL. Нынешняя подписка на сессию обновляет только Game Details, не вызывая syncDialogs.

## QA-04 — P2: ошибка сохранения имени оставляет незавершённую регистрацию

**Место:** [src/services/firebase.ts](../src/services/firebase.ts), строки 60–72.

**Воспроизведение:** создание аккаунта Firebase завершается успешно, затем updateProfile завершается сетевой ошибкой. Повторить регистрацию с тем же email.

**Фактически:** обработчик только вызывает signOut, но уже созданный аккаунт остаётся. Повторная регистрация получает `auth/email-already-in-use`; выбранное имя не сохранено. Состояние моделировалось на границе SDK в отдельном тесте; реальный сетевой сбой при регистрации специально не создавался.

**Ожидание:** предоставить восстановление незавершённого сохранения профиля, либо выполнить контролируемый откат только что созданного аккаунта. Пользователь не должен получать общую ошибку, за которой скрывается уже завершённое создание аккаунта.

## QA-05 — P2: real-time проверка принимает некорректный email

**Место:** [src/features/auth/validation.ts](../src/features/auth/validation.ts), строка 8; [src/components/dialogs/auth-dialog.ts](../src/components/dialogs/auth-dialog.ts), form.noValidate.

**Воспроизведение:** открыть Register, указать `AuditTester`, email `qa@example..com` и одинаковые пароли, удовлетворяющие правилам формы.

**Фактически:** Create Account доступна, ошибки email нет, aria-invalid равен false. При этом браузер сообщает `input.validity.valid === false`. Нативная блокировка отключена через noValidate. То же значение проходит функцию валидации Login. Подтверждено в браузере и отдельным тестом.

**Ожидание:** отклонять пустые части домена и показывать ошибку при вводе, согласовав пользовательскую проверку с validity email-поля.

## Дополнительный незавершённый функционал вне указанных баллов

- **Forgot Password:** вместо восстановления пароля показывает текст с адресом поддержки. Отправки reset email нет; кнопка в src/components/dialogs/auth-dialog.ts, строки 373–380. Указанные критерии отдельно восстановления пароля не требуют.
- **Play Now:** кнопка явно disabled и содержит подсказку `Game launching is not available yet`; запуск игры не реализован. Это тоже вне приведённых критериев Story 4.
